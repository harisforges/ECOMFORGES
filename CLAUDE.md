# Working in this repo

## "Feed it to the brain"

When Haris says **"feed it to the brain"**, or anything meaning the same thing,
that is an instruction to **write what he just gave into the brain section of
`ROADMAP.md`** — the section headed *"Decided: one brain, built before the super
app"*. It is not a request to build anything.

The brain has no store yet, so `ROADMAP.md` is where its contents live until it
does. Put the record under the right heading in that section, or add a heading
if none fits.

What goes in is subject to the brain's own rule, written in that section: verify
it against its spec, double-check it against what the section already holds, and
only then write it. If it fails either pass, say so and drop it — do not write a
half-record or park it somewhere "for later". That rule is the point of the
brain and it applies to the roadmap copy of it too.

**The brain has no name yet.** Do not invent one. Call it "the brain" until
Haris names it, then rename it everywhere at once.

## Orientation

- `ROADMAP.md` is the decision record. Decisions live there so they survive
  between sessions and between people. Read it before proposing direction.
- Seven tools, each a self-contained HTML file at the repo root, served by
  GitHub Pages and Firebase Hosting. `app/index.html` is an unfinished,
  unlinked client-portal prototype.
- `content/firebase-rules.md` holds database rules that are **not yet applied**.
  Until someone pastes them into the Firebase console, ForgeSprint, ForgeBilling
  and ForgeAgreement cannot save anything.
- Work on a branch, open a PR, and say what was verified rather than that it
  should work. Daniel Qayyum commits to `main` directly, so re-read a file
  before assuming it is as you left it.
